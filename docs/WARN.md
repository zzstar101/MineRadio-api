## 修改说明

**下称网易云音乐为 N，QQ 音乐为 Q，Soda Music 为 S。**

### N

| 方向     | 说明                                                                                      |
| ------ | --------------------------------------------------------------------------------------- |
| cookie | NMTID 由服务器返回，疑似触发原因为在不携带 NMTID 的情况下访问 EAPI 类型接口的任意 URI。                                 |
| rcmd   | 设计之初只针对歌单、单曲、专辑设计了响应结构，而推荐页模块 1 的卡片类型较为复杂，只能通过 ID 头标识符结合内容进行分发。因此，推荐页部分 ID 无法脱离本项目单独使用。 |

### Q

| 方向       | 说明                                                        |
| -------- | --------------------------------------------------------- |
| checksum | 放在动态链接库中的算法目前尚未在网络上公开。直到有超过 2 人在 GitHub 上公开该算法后，我们才会考虑公开。 |
| song-url | 客户端选择获取加密或未加密 URL 的行为目前尚未完全理解，因此 QQ 音乐容易出现换源问题。           |

### S

| 方向       | 说明                                                                             |
| -------- | ------------------------------------------------------------------------------ |
| checksum | 依赖附加包，即 `.bin` 文件。目前由动态链接库操控 `.bin` 文件实现校验，尚未获取到直接的算法实现，等待有人逆向出源码。             |
| login    | 登录二维码理论上是由 Token 构建出包含设备名和平台信息的新二维码，不过目前没有实现，因为响应体本身已经包含一个 Base64 编码的 QR Code。 |

### 通病

| 方向    | 说明                                                                        |
| ----- | ------------------------------------------------------------------------- |
| model | 响应体若缺失字段，可能会在反序列化流程中失败。若遇到此类情况，可以 dump 原始 `resp`，并将对应字段增加为 `Option`，详见文末。 |

可搭配 [test_mineradio_api](https://github.com/cXp1r/test_mineradio_api) 进行调试。
